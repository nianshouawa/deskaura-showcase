# DeskAura 零基础项目教程与实现总方案

本教程以 2026 年 11 月 11 日的项目源码为依据。它面向没有编程经验、希望通过 DeskAura 学习桌面应用和 AI 工程的读者。读完后，你应当能区分界面、后端、模型和数据，找到一项功能对应的代码，完成一个小修改，并知道怎样测试和打包。

DeskAura 已经有 Windows 安装包，但“能打包”不等于“所有电脑都验证过”。当前安装包未签名，尚未完成独立干净 Windows 机器的安装验收。学习时先用测试角色和空白文件夹，不要把真实密钥、重要文件和日常角色当作实验材料。

## 阅读路线

第一次接触编程，按第 1 至第 5 章建立概念，再按第 6 至第 16 章追踪功能。准备动手时，阅读第 17 至第 22 章。最后的目录与排错表可以当作查询手册。

不要试图一次记住所有文件名。先跑通一个动作，再找到它经过的文件，最后才修改。教材里的示例地址、文件名和角色都只是练习值，不能当作你的实际配置。

## 1 先认识这个程序

### 1.1 用户看到的功能

DeskAura 在 Windows 桌面上显示一个三维角色。用户可以导入模型、应用角色、打开对话、配置声音和模型服务，也可以在明确授权后让角色读写文件或调用工具。人脸检测、语音识别、文字生成、语音合成、动作播放不是同一项技术。

角色的外观来自模型文件。角色说什么主要由对话模型决定。嘴巴、表情和骨骼运动由前端播放器控制。把一个更聪明的对话模型接进来，并不会自动修好手腕角度；换一个外观模型，也不会自动带来语音识别能力。

### 1.2 不能混为一谈的概念

| 概念 | 通俗解释 | 在项目中的例子 |
| --- | --- | --- |
| 程序 | 规定步骤并执行步骤的软件 | DeskAura 桌面程序 |
| 模型 | 学习得到的参数或三维资源 | 对话模型与 VRM 角色模型含义不同 |
| API | 程序之间约定好的调用入口 | 请求本机 8000 端口发送聊天 |
| API Key | 服务商识别账号和扣费的凭证 | 用户自己填写的云端密钥 |
| 运行环境 | 执行某类代码的软件 | Python 执行后端源码 |
| 依赖包 | 别人写好的可复用代码 | Vue、Three.js、FastAPI |
| 数据 | 用户使用后产生或导入的内容 | 会话、记忆、角色配置 |
| 缓存 | 为避免重复计算而临时保存的结果 | 下载后的短期动作数据 |

### 1.3 安装版与源码版

安装版用于日常使用。安装包已经包含后端执行所需的应用运行库，所以普通启动不要求用户另装 Python 或 Node。若用户要求运行 Python/JavaScript 代码，或配置依赖这些环境的 MCP 服务，仍需要对方电脑上具备相应环境。

源码版用于学习和开发。Python、Node、npm、Rust 和 Windows 编译工具负责安装依赖、运行源码、编译与打包。它们是开发工具，不应全部复制进发给朋友的安装包。

## 2 从零理解编程工具

### 2.1 文件与目录

目录就是文件夹。路径告诉程序文件在哪里。绝对路径从磁盘开始，例如 D:\Study\demo.txt；相对路径从当前目录开始，例如 docs\learning-guide.md。当前目录不同，同一条相对路径可能指向不同位置，这是很多启动错误的来源。

扩展名表示文件用途。.py 是 Python 源码，.ts 是 TypeScript，.vue 是 Vue 组件，.rs 是 Rust，.json 是结构化数据，.md 是 Markdown 文档，.ps1 是 PowerShell 脚本。不要因为文件能打开成文字就随意修改。

### 2.2 终端与命令

PowerShell 是输入命令的窗口。命令不是聊天内容，它会真实执行。cd 用来切换目录；运行脚本前先确认所在目录。路径中包含空格时要加双引号。遇到报错先读第一处错误，不要反复执行安装或删除命令。

```powershell
cd "D:\Agent code\Project\DeskAura"
Get-Location
Get-ChildItem
```

第一行进入项目，第二行显示当前位置，第三行列出文件。以上是查看命令，不会改动角色数据。

### 2.3 Python 与虚拟环境

Python 解释器负责运行 .py。pip 安装 Python 依赖。.venv 是该项目的独立依赖环境，避免不同项目互相覆盖包版本。删除 .venv 通常不删源码，但会让源码启动和后端打包不可用，恢复需要重新安装依赖。

项目目前以 Python 3.12 开发后端；某些外部 MCP 服务可能要求不同版本，不能因为电脑有一个 Python 就认定所有服务都兼容。

### 2.4 Node 与 npm

Node 执行 JavaScript；npm 安装前端依赖并执行 package.json 中的命令。node_modules 是下载的依赖，package.json 描述项目需要什么，package-lock.json 记录实际解析结果。保留锁文件有助于别人得到相近的依赖组合。

npm run build 不会把你的 Vue 源文件改成安装包。它先做类型检查，再生成浏览器可读的前端文件；桌面外壳和后端还需要各自的构建步骤。

### 2.5 Rust 与 Cargo

Rust 负责桌面系统层。Cargo 是 Rust 的依赖和构建工具。Cargo.toml 是配置，Cargo.lock 是依赖锁定文件，target 是编译产物。target 中很多缓存可以重建，但当前可运行的 deskaura.exe 和配套资源也在其中，不能整目录盲删。

### 2.6 Git

Git 保存源码版本变化。.git 不是普通缓存。它使你能够比较修改、回看历史、建立分支。Git 不自动备份所有用户数据，也不应保存 API Key。查看差异时先运行 git status，再用 git diff 理解变化。

练习：只修改一行文档，再查看 git diff。你应当能看到改前与改后的那一行。暂时不要学习强制重置或清空工作区的命令。

## 3 整体架构

### 3.1 为什么拆成几部分

界面刷新需要及时，云端模型可能等待几十秒，语音和三维资源又有各自的生命周期。因此项目把用户界面、Windows 外壳、对话编排、记忆和动作分开。这样可以单独测试，也能让某个云端服务失败时给出明确提示。

这不代表它是部署在很多服务器上的大型系统。默认桌面程序会在同一台电脑上启动三个本机服务，通过 HTTP 通信。

```text
用户
  |
Vue 界面和 Three.js 角色
  |                 |
本机 HTTP            Tauri 原生命令
  |                 |
Agent 8000           Rust 与 Windows
  |       |
Memory   Motion
8001     8002
  |       |
本地索引  动作库或动作云服务
```

### 3.2 各层的职责

前端处理按钮、输入、界面状态、录音采集、三维渲染和播放。Rust 处理窗口、托盘、文件选择器、设备授权等系统交互。Agent 接收消息，组合人设和记忆，调用对话服务，核验工具操作并组织回复。

Memory 保存与检索长期记忆。Motion 选择本地动作或请求生成服务。外部对话、语音和动作 API 不属于 DeskAura 自己的后端，它们有独立账号、额度、网络和协议限制。

### 3.3 端口和本机地址

127.0.0.1 表示这台电脑自身。8000、8001、8002 是三个后端入口，开发前端通常使用 1420。端口相同不代表服务相同；端口被其他进程占用时，新服务可能启动失败。

健康接口只说明进程能够回答请求，不代表 API Key 正确、摄像头识别人脸或声音播放成功。不要把健康检查当作全部功能验收。

## 5 先跑起来再学习

### 5.1 普通使用

打开 release 中的安装包，按步骤安装。首次启动没有你的私人角色和服务配置。先导入有使用权的角色模型，在主页选择并应用，再打开设置。优先配好大脑，确认文字对话，再启用声音和动作，最后测试本地工具。

每次只接通一个模块。这样出问题时能明确是新启用的模块，而不是同时排查八个模块。

### 5.2 查看开发环境

```powershell
python --version
node --version
npm.cmd --version
rustc --version
cargo --version
```

这些命令只查看版本。缺少 Rust 或 MSVC 构建工具时，前端网页可能仍能跑，但 Tauri 编译会失败。Windows 桌面开发需要对应的编译工具链，具体安装界面以官方文档为准。

### 5.3 安装项目依赖

scripts/setup.ps1 负责建立 Python 3.12 虚拟环境、安装三个服务依赖和前端依赖。它可能联网、安装软件或下载包，因此先阅读脚本，再决定执行。不要为了消除一个报错就升级全部依赖。

注意一个现存的重建风险：Agent 和 Memory 的 requirements 要求 pydantic 大于等于 2.12.4，而 Motion 的 requirements 仍固定 2.10.3。把三份 requirements 一起安装时可能冲突。现有环境能测试通过，不代表从空环境安装一定成功。重建前应先统一并验证依赖版本；本轮文档清理不擅自修改应用依赖。

### 5.4 源码开发启动

已有可用 .venv 和 node_modules 时，可以执行 scripts/start.ps1。它启动三个后台服务，再启动 Vite。浏览器预览不等于完整桌面环境：托盘、透明窗口、原生设备授权等应在 Tauri 中测试。

```powershell
cd "D:\Agent code\Project\DeskAura"
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

不要同时启动安装版、发布版和多份源码后端，它们默认争用相同端口。需要停止时先辨认该进程的程序路径，不要把电脑所有 Python 或 Node 进程一起杀掉。

## 6 前端页面怎样组织

### 6.1 页面入口

companion-frontend/src/main.ts 读取窗口网址的查询参数。home 对应 Home.vue，settings 对应 Settings.vue，tutorial 对应 Tutorial.vue，其他情况进入 App.vue。多个窗口使用同一个前端构建，但选择不同的根组件。

App.vue 不只表示主页。它承担桌面角色和聊天等大量交互，不能因为名字常见就认定其他页面没用。

### 6.2 Vue 组件

一个 .vue 通常包含 script、template 和 style。script 写状态与行为，template 写界面结构，style 或公共 CSS 决定外观。组件把重复界面封装起来，例如 RoleModulePanel 管理角色模块，McpServicesPanel 管理 MCP 服务。

Vue 的 ref 保存可变化状态。修改 ref 后，相关界面会更新。computed 表示从其他状态推导出的值。watch 监听变化执行工作，例如切换角色后重新加载配置。

### 6.3 为什么会出现旧结果覆盖新角色

假设角色甲正在检测，用户切换到乙，甲的网络请求稍后才返回。如果直接把结果写入当前界面，乙就会显示甲的状态。项目用角色标识、请求版本号或取消信号限制这种回写。

正确思路是发请求时记住角色和版本，返回时重新比较，不符合就丢弃结果。这比“等网络快一点”可靠，也适用于搜索和模型加载。

### 6.4 样式与设计

settings.css、guide.css、studio.css 等分别处理不同界面。修改间距前先定位具体选择器；不要全局修改所有 div 或所有按钮。指南和设置可以共享视觉风格，但不意味着窗口边距和字号必须完全一致。

角色描述、角色设定、MCP 服务和 JSON 配置溢出时，右下角斜线可展开或收起。ExpandableContent.vue 共用测量逻辑：默认高度是下限，文本通过屏幕外的临时副本测量，不压缩正在编辑的输入框，避免滚动跳顶。展开不是保存。主页描述最多两行，超出省略，模型预览区不随描述长短改变。

练习：找到使用指南的一段普通说明，改一个词，运行前端测试与构建，再看界面。不要以这个练习改权限逻辑或接口地址。

## 7 一条聊天消息经过哪里

### 7.1 前端发送

用户输入后，前端通过 api.ts 封装的请求访问 Agent。角色标识通过 X-DeskAura-Role 传递，会话标识放在请求中。附件有数量和格式限制，不能把任意文件无限制塞进 JSON。

```json
{
  "message": "你好",
  "session_id": "练习会话",
  "user_emotion": null
}
```

这是便于理解的字段示例，不是完整的会话创建流程。真实界面先建立合法会话，再发送消息。不要把任意字符串当作所有角色通用的会话 ID。

### 7.2 Agent 接收

agent-backend/app/main.py 声明 HTTP 路由，并用 Pydantic 检查请求字段。装饰器 @app.post 表示这里处理一种 POST 请求。校验错误不会直接回显完整附件或密钥，以减少泄露风险。

main.py 的角色中间件先确定当前请求所属角色，再执行路由，结束后恢复上下文。ContextVar 是异步代码中的请求上下文工具，不是永久配置数据库。

### 7.3 LangGraph 编排

graph.py 中的 CompanionGraph 定义 load_context、generate_reply、plan_motion、persist_turn 四个节点。它们依次加载上下文、生成回复、安排动作并保存本轮。

“图”表示可连接的执行步骤，并不等于画面里的三维场景。节点也不是四个大语言模型，每个节点只是承担一类工作。

### 7.4 回复与副作用

一句“文件已经保存”只是文字。真正保存必须经过 FileTools，得到真实回执。模型想执行操作时会返回结构化动作，由后端检查权限、路径、当前用户意图和批准策略。

工具运行后，后端把真实结果交给模型继续。如果还有必要步骤就继续工具循环；需要用户批准时返回确认卡。当前循环有步骤和恢复次数上限，不是无限运行的自主代理。

## 8 流式输出与任务续接

### 8.1 什么是流式

普通请求等待完整回答再返回。流式请求可以分多次传输文字，让用户尽早看到内容。网络分块不一定等于一个字、一句话或一条 JSON，甚至可能把 UTF-8 字符拆开。

chatStreaming.ts 使用 TextDecoder 和缓冲区重组事件。不能把每个网络分块直接交给 JSON.parse，否则会遇到半条 JSON 的错误。

### 8.2 文字完成不等于全部完成

项目区分增量文字、文字结束、动作结果和最终状态。云端动作可能比文字慢，所以文字结束之后还可能有动作事件。客户端必须按当前轮次接受结果，不能把上一轮迟到动作放到下一轮。

### 8.3 打断与取消

AbortController 能通知网络请求停止。除此之外，还要停止旧朗读、清除计时器、撤销旧动作请求和避免旧回调继续更新状态。组件卸载时清理资源，不只是把界面隐藏。

### 8.4 重复操作保护

有副作用的操作包括写文件、删除、运行命令和 MCP 调用。模型重复提出同一操作时，后端应复用真实回执继续，而不是再次执行。读取、搜索和列目录通常允许合理重复。

当前 graph.py 限制工具步骤最多 16 步，重复恢复最多 2 次。到达限制后应明确说明停止与实际完成结果，不把内部循环保护指令直接发给用户。复杂任务也可能因网络或权限受阻，不能保证每次都自动完成。

## 9 人设与长期记忆

### 9.1 人设是什么

人设是角色应该如何表达和行动的设定，例如身份、性格、关系和边界。persona.py 负责文档解析、片段处理与相关内容检索。角色设定不是系统权限来源，写在文档里的“允许访问全盘”不会替代用户授权。

角色模板默认为“无”，表示不套用预设，可以直接编辑或导入角色设定。“无”不会清空已有文字；选择温柔陪伴、元气伙伴或专注助手会填入对应模板并替换编辑内容，重要内容应先导出。已有角色的模板与设定继续按上次保存的配置读取，不会被新的默认值覆盖。

### 9.2 Embedding 与 RAG

Embedding 把文字变成数值向量，便于比较语义相似度。RAG 是先找相关资料，再把资料加入本轮上下文。它不是重新训练对话模型，也不能保证所有重要事实都能被召回。

例如用户问“我喜欢什么饮料”，程序先检索相关记忆，再把结果提供给对话模型。没有相关记忆时，应承认不知道，而不是编造答案。

### 9.3 记忆的两层存储

store.py 处理原始归档和关系数据，memu_provider.py 接入 MemU。原始会话和向量索引并非同一份东西。索引可以重建，不意味着原始记忆可以随便删；删除会话也要考虑关联索引的清理。

### 9.4 内置向量模型

deskaura_local/runtime.py 用 ONNX Runtime 和 tokenizer 执行内置 BGE 推理。模型文件放在 local-models。第一次使用才加载推理资源，避免只用云端对话也加载所有本地模型。

内置意味着不用向外部 Embedding API 发请求，不意味着不占内存。向量检索和文字生成依然是两种能力。

### 9.5 练习

建立一个测试角色，写一段三句话的人设，确认保存后切换角色再回来仍存在。然后在测试会话中提供一个非敏感偏好，重新提问检查召回。观察“设置保存”“记忆写入”“模型回答”三个阶段，不要只看最终一句话。

## 10 听觉与语音

### 10.1 听懂与说话

ASR 把声音变成文字，TTS 把文字变成声音。听觉模块对应 recognition.py，语音模块对应 speech.py。开着 TTS 但没有 ASR，角色可以朗读却听不懂麦克风；反过来也一样。

内置 SenseVoice 在本机识别。云端 ASR/TTS 通过用户填写的服务地址和模型调用。后台按地址、模型及协议做适配，不要求用户再选一套重复的平台表单。

### 10.2 麦克风采集

浏览器环境使用媒体设备接口，桌面版还经过 Rust 的设备授权入口。Windows 隐私设置、DeskAura 的授权记忆和一次实际采集请求是不同层次。程序记住用户同意，不代表可以绕过 Windows 禁止访问。

### 10.3 通话模式

CallVoiceControl 处理连续通话中的录音、分句与状态。通话仍然经过语音识别、聊天和朗读，不应仅因为按钮长得像电话，就认为它使用运营商电话网络。

挂断、静音、关闭听觉和隐藏窗口都涉及资源清理。排查“听觉已停用”时，先看当前角色的 asr_enabled 和角色作用域，再看设备权限和服务连接。

### 10.4 分句朗读

SpeechSentenceBuffer 根据标点和长度先输出完整语句，避免等整段长回答才说话。代码块不应该逐字符读出来。播放器要在切换角色、打断和卸载时停止，并释放音频对象地址。

## 11 视觉与隐私

### 11.1 人脸追踪

内置视觉用 BlazeFace 检测人脸，faceTracking.ts 计算追踪信号，再驱动头部和视线。它检测画面中的脸，不等于识别你的真实身份。眼睛是否能动，还取决于角色是否提供眼骨或相应形变。

摄像头画面正常、检测到脸、前端上报回执和模块显示正常是多个步骤。设置检测应打开选定摄像头，确认检测后释放自己持有的设备资源。

### 11.2 预览不等于上传

本地摄像头预览和人脸检测，不等于向云端发送照片。聊天查看屏幕或摄像头是另一个流程：需要服务支持图片输入、用户有本轮查看意图，并确认采集。

短时采集发送的是有限数量的时序图片，不是完整视频，也不包含音频。不要把图片采样宣传成视频理解能力。

### 11.3 CameraLease

CameraLease 管理一段摄像头流的归属与释放。停止时要对 tracks 调用 stop，并清理视频引用。多个窗口可能各自使用设备，不能把一处关闭误当全部设备都释放。

练习：在测试角色中执行一次视觉检测，观察摄像头指示灯是否在结束后恢复。若当前桌面追踪仍开启，指示灯继续亮可能是另一个合法使用者，不一定是泄漏。

## 12 三维模型与动作播放

### 12.1 场景与骨骼

Three.js 管理相机、灯光、模型和渲染。VRM 为人形角色提供统一骨骼和表情约定。骨骼改变旋转带动蒙皮，表情通常改变形变权重。

模型原点、朝向、身高和骨骼绑定不同，不能把云端骨骼角度原封不动套给所有角色。播放器需要规范化、重定向和安全限制。

主页模型预览是静态展示，使用普通鼠标光标，不响应角色拖动、旋转或缩放。已应用桌宠可用中键调整视角、滚轮缩放。cameraBounds.ts 根据加载时模型边界建立绕中心的包围球，缩放范围不随转动方向重算。同一最终视角的最大缩放与操作顺序无关，到达上限后不会反向缩小；初始取景保持原设计。

### 12.2 动作数据

本地动作文件包含 fps、poses、trans 和 duration 等字段。当前规范化 SMPL-H 数据每帧有 156 个数，对应 52 个关节的三维轴角。轴角不是屏幕上的像素坐标。

fps 表示每秒帧数。时长应由有效帧数除以 fps 或解析后的轨道决定，不应该只相信一个文字标签。

### 12.3 腾讯 FBX 路径

tencent_motion.py 提交生成任务、轮询结果；动作服务下载并缓存 FBX；前端 fbxMotion.ts 解析轨道，再转换到统一的人形数据。下载地址可能包含临时认证信息，不直接当聊天内容暴露。

解析成功仍不等于视觉效果正确。还需要检查脚底、膝盖、肩膀、手心、手腕和模型朝向，必要时用不同角色验收。

### 12.4 播放与安全修正

motionPlayback.ts 负责轨道准备与插值，motionSafety.ts 负责关节、碰撞和语义姿势修正，AvatarStage.vue 将结果应用到角色。四元数用于表示旋转，插值用于在两帧之间得到平滑姿势。

“平滑”不是越慢越好。过强插值会让转身拖泥带水；过弱会暴露帧跳动。修手腕时只改手腕，不应顺手改变肩膀和脚步。这也是动作测试要对其他关节保持不变做断言的原因。

## 13 动作模式与待机调度

### 13.1 在线离线混合

在线模式请求配置的动作生成服务，失败不能伪装成在线成功。离线模式只选已有本地库；这里的“离线”仅指动作来源，不代表对话、语音等全部离线。混合模式普通回复用本地情绪动作，明确动作请求优先生成，失败可本地兜底。

自动时长只接受动作模型原生预测；手动时长发送用户指定值。当前腾讯接口适配会把手动秒数限制到支持范围并取整。Worker 缺少原生预测能力时应明确报错，不能静默用默认秒数冒充自动预测。

### 13.2 待机条件

standby.ts 的两个触发条件是人脸明确离开 10 秒，或 60 秒没有交互。摄像头失败或未知状态不能当作用户离开。关闭待机开关或角色正在忙时，不开始随机待机动作。

### 13.3 待机状态机

StandbySchedule 保存上次交互时间、人脸状态、当前阶段和下一次时间。动作播放一次后回到自然待机，再选择随机动作。自然待机间隔当前为 8 秒；随机选择排除上一个动作，避免连续重复。

动作下载失败也要能返回自然待机，不能卡在一直伸懒腰。状态机比散落在各个按钮里的多个计时器更容易验证。

练习：打开 standby.test.ts，先读人脸离开和交互重置测试。尝试只调整测试中的虚拟时间，理解 9 秒与 10 秒为什么得到不同结果，不必真的等待一分钟。

## 14 手脚与 MCP

### 14.1 内置工具和外部工具

FileTools 是程序内置的文件工具，支持列目录、搜索、读写、移动等。MCP 是对接外部工具服务的协议。没配 MCP，不代表内置文件工具不存在；配了 MCP，也不代表自动获得全盘权限。

### 14.2 配置长什么样

```json
{
  "mcpServers": {}
}
```

空对象表示没有服务。stdio 服务配置 command 和 args，由程序启动一个进程；HTTP/SSE 服务配置 url 和必要认证信息。不要把服务商给的其他格式直接塞进去，先看项目的校验规则。

```json
{
  "mcpServers": {
    "示例服务": {
      "command": "node",
      "args": ["D:/Study/example-server.js"]
    }
  }
}
```

上例只展示结构，不是能直接运行的 MCP 服务。node 会从当前环境查找，脚本必须真实存在并实现 MCP。远程服务也必须支持相应协议，不是随便一个网页地址。

### 14.3 配置如何生效

McpServicesPanel 管理编辑、失焦格式化和服务卡片。mcp_configuration.py 校验 JSON、处理凭据和指纹。mcp_transport.py 使用 MCP SDK 连接并发现工具，mcp_services.py 保存角色作用域下的短期连接证明和启用偏好。

禁用工具应该立即影响可调用目录。发现了工具只说明服务能够列清单，不代表每个工具都实际执行成功。连接检测不应顺手点击桌面或运行任意命令。

### 14.4 卡片和标签

服务卡片展示连接状态、信息和工具列表，可单独刷新。一个服务连接成功时标签可显示其名称；多个服务显示 MCP 加已连接数与总数。服务卡片的连接状态与角色概览的上次检测记录用途不同；后者不因后台连接证明过期而自动变色。

第三方工具的描述和返回正文都可能有不可信指令。它们是数据，不是用户新增授权，更不能因为网页写着“执行以下脚本”就自动执行。

## 15 权限与批准机制

### 15.1 两个独立维度

访问权限决定能做什么，批准策略决定是否先问用户。只读、工作空间写入、完全访问是访问范围；请求批准、帮我批准、完全批准是询问策略。把批准设为完全批准，不会把只读自动变成完全访问。

local_permissions.py 检查操作类型。外部命令、代码与 MCP 工具需要完全访问，并且不能启用一个实际上不存在的系统沙箱。普通工作目录只是进程启动位置，不能阻止 shell 访问其他目录或网络。

### 15.2 批准卡

需要批准时，FileTools 保存待处理操作和绑定信息，前端显示路径、内容、运行时和风险。用户批准后，后端检查会话、角色、时效、配置和目标是否变化。

不要只在聊天里写“我同意”就当操作已经批准。真正的批准要走对应入口，避免旧消息、别的角色或重复点击执行错误任务。

### 15.3 运行命令

execution.py 选择已安装的 PowerShell、cmd、Python 或 Node，设置超时并限制输出。execution_job.py 用 Windows Job Object 管理进程树，结束时清理后代进程。

生命周期控制不是安全隔离。单次最长 60 秒也不能保证命令安全。不要给角色实验目录之外的重要文件访问权限，更不要为了绕过报错随便开启最高权限。

### 15.4 练习

新建空白练习目录，只授权该目录。先列目录，再请求创建 hello.txt，查看批准卡，批准后自行打开文件确认。最后测试拒绝批准，验证没有产生第二个文件。练习不需要删除系统文件、修改注册表或运行网络下载脚本。

## 16 数据保存与连接状态

### 16.1 角色隔离

角色有 ID，后端用哈希目录名保存配置和记忆。哈希只是稳定的目录标识，不是加密。相同外观模型导入为两个角色，仍可有独立设定和会话。

会话命名空间、角色请求头、凭据名和异步结果都要绑定同一角色。只隔离一个 config.json 远远不够。

### 16.2 数据在哪里

从项目目录运行的桌面版通常使用项目旁边的 DeskAura-Data。安装到独立位置的版本使用当前用户 LocalAppData/com.deskaura.app。角色模型等前端资料可能保存在 WebView IndexedDB；凭据由 Windows 凭据管理器保存。

因此“导出配置”不是完整备份。完整备份需考虑应用数据目录、模型资料和凭据重新配置。不要把配置导出当作能带走 API Key 的文件。

### 16.3 保存与检测

保存修改持久化配置，并向其他窗口发出配置变化事件；检测验证服务是否真实可用。具体模块有各自的检测流程，保存和检测不能混成一个真假不明的状态。

角色已应用不是禁止修改配置的条件。保存完成后直接通知各窗口，不等待窗口确认才结束保存；结果会区分“配置已保存”和后续检测失败。检测未通过不表示刚保存的字段没有写入。描述移开焦点自动保存，人设正文需要保存配置。MCP 服务区域随卡片自适应，默认最大高度与 JSON 框一致，空列表保留单卡片高度。

主页与设置的模块开关、本地操作策略和工作空间立即同步并自动保存，不触发模块检测。修改仅应用于同一角色；角色关闭后再开启保留上次主动检测的结果。只有明确点击保存配置或检测才更新角色概览的检测记录。MCP 的 JSON 失焦和工具启停也不自动检测；底部保存配置会检测全部服务，单独检测只检查已保存配置。

已配置表示字段存在；已连接表示通讯或工具发现成功；完整检测还可能要求识别、播放或数据回读。待复检、停用和异常也不是同一件事。

### 16.4 状态有效期

后端短期证明绑定配置指纹，配置变化会使旧证明失效；运行时仍按实际配置与权限判断。界面使用 moduleDetection.ts 保存的角色独立历史记录，主页和设置立即同步，不轮询覆盖，不因切换开关抹掉记录。历史绿色不保证此刻在线，变更参数、设备或服务后需要主动检测。显示记录与运行时证明分开，既避免状态反复闪烁，也不把旧记录当作执行权限。

## 17 内存磁盘与资源释放

### 17.1 两种占用

内存是程序运行时的 RAM；磁盘是文件占据的空间。C 盘减少几十 GB 不能单凭现象判定内存泄漏。可能是编译缓存、模型下载、临时解包、日志或其他程序文件，需要先定位目录。

项目给动作结果设置数量、时间和 FBX 字节上限；角色相关的部分缓存也做了淘汰。它们降低长期增长风险，但不是已经证明任何使用时长都绝无泄漏。

### 17.2 前端释放

Three.js 的几何体、材质、纹理、渲染器需要正确释放；媒体流需要停止轨道；Blob URL 需要撤销；计时器和事件监听要取消；未完成请求要中止。把 JavaScript 变量设为 null 不一定释放 GPU 或摄像头。

### 17.3 可以清理什么

构建中间产物、pytest 缓存、Python 字节码和测试临时目录通常可重建。clean_workspace_caches.ps1 只清理项目内列明的缓存，并校验 release 安装包未变；执行前仍应阅读脚本和确认没有构建正在进行。

不能盲删 .git、.venv、node_modules、local-models、local-mcp、motion-service/data 或用户数据。即使某项技术上可以重新下载，也不代表它对当前运行无用。

## 18 怎样读懂代码

### 18.1 函数与类

函数是可重复调用的一段操作，参数是输入，返回值是输出。类把相关状态和操作放在一起。例如 CameraLease 有摄像头状态和 start/stop 行为；StandbySchedule 有时间状态和 tick 行为。

先问“这段代码输入什么、改变什么、输出什么”。遇到陌生关键字先查定义，不要逐行机械翻译成中文。

### 18.2 异步

async/await 用来在等待网络或设备时让出执行机会，不意味着另一个线程，也不保证操作顺序永远正确。await 前记住角色，await 后核对角色，是防止迟到结果污染的重要模式。

asyncio.to_thread 把同步工作放到线程中，避免阻塞异步服务。共享字典同时被多线程修改时需要考虑锁；锁本身不能解决错误的数据归属。

### 18.3 类型与校验

TypeScript 类型帮助开发时发现错误，Pydantic 校验检查实际请求。两者不能互相代替。前端写了某字段为数字，外部调用者仍可能发送字符串或超大对象，后端必须自己检查。

### 18.4 找入口的方法

想查摄像头：从 Settings 的检测按钮找到 testRoleModule，再追到 detectFaceSample、CameraLease 和原生命令。想查权限：从确认卡找到批准请求，再读 FileTools.decide 和 local_permissions。一次只跟一条路径。

## 19 如何修改而不破坏功能

### 19.1 小范围修改

先写下预期行为，再定位最小模块。调整指南边距通常只改 guide.css；改变待机时间先看 standby.ts 和测试；改变接口字段要同时检查前端、后端和测试，不能只改一边。

不要为了“代码看起来复杂”就拆掉异步取消、角色校验或配置指纹。那些判断往往是为了处理真实竞态，不是多余代码。

### 19.2 测试方法

单元测试检查一个函数；组件测试检查按钮和状态；服务测试检查接口与权限；打包自检检查执行文件是否带齐动态依赖。模拟云端成功不等于用户账号当前真的成功。

测试应覆盖失败：超时、拒绝批准、切换角色、关闭窗口、设备不存在、工具禁用、配置修改和旧请求返回。这些比只测“正常点击一次”更容易发现问题。

### 19.3 第一个功能练习

选择“调整自然待机间隔”。先在 standby.ts 找 STANDBY_IDLE_MS，再看 standby.test.ts 如何推进虚拟时间。写出“随机动作结束后自然待机至少多少秒”的预期，然后同时修改常量和相应测试。

完成后运行测试并实际观察角色。若只改测试期待值使它通过，却没有理解行为，就没有完成这个练习。练习结束恢复日常偏好的间隔，不要误把实验参数作为正式发布设置。

## 21 打包与发布

### 21.1 构建链

npm run tauri:build 先调用 build_backend.ps1，用 PyInstaller 打包三个服务的共同运行程序；然后构建前端，再由 Cargo 编译 Tauri，最后由 NSIS 生成安装包。

Python 的 onedir 产物是执行文件加 _internal 依赖目录，不是一个 exe 包含一切。不能单独复制 deskaura.exe 或后端 exe 给朋友，遗漏配套资源会导致启动失败。

### 21.2 执行命令

```powershell
cd "D:\Agent code\Project\DeskAura\companion-frontend"
npm.cmd run tauri:build
```

安装包生成在 src-tauri/target/release/bundle/nsis。release 目录是整理后的对外文件集合，里面安装包、说明和 SHA-256 应对应同一版。

### 21.3 隐私检查

打包清单只能包含程序代码、内置模型、动作和必要依赖。不能加入 DeskAura-Data、聊天数据库、Windows 凭据、开发者模型、MCP 浏览器 profile 或私人 JSON。扫描明显密钥只能降低风险，不能取代清单审查。

开发机上可以复用已有 Python/Node；朋友电脑不能引用你的 D 盘路径。MCP 默认空白，由使用者配置自己电脑的命令或远程服务。外部 MCP 包并未随应用自动分发。

### 21.4 安装验证

验证不同安装目录、没有开发工具的机器、首次配置、设备授权、普通对话、更新和卸载。电脑已有项目安装记录时，不要为了测试直接静默安装覆盖项目目录。

当前安装包未签名。公开发布应考虑自己的签名证书、许可证清单、版本管理和干净机器验收。不要教用户关闭防病毒软件来绕过警告，也不要承诺“绝无误报”或“绝无 bug”。

## 22 常见问题排查

| 现象 | 先检查 | 不应采取的做法 |
| --- | --- | --- |
| 窗口出现但无法对话 | 大脑模块、账号额度、服务地址 | 同时重装全部依赖 |
| 提示听觉停用 | 当前角色听觉开关和 ASR 设置 | 只检查语音合成 |
| 摄像头能预览但标签异常 | 人脸回执、选定设备、角色归属 | 写死绿色状态 |
| 文件操作权限不足 | 访问权限、工作空间、批准策略 | 认为完全批准等于完全访问 |
| 没有批准卡 | 是否产生结构化操作与待处理记录 | 让用户反复口头同意 |
| 切换角色出现旧回复 | 旧请求取消和回写条件 | 只延长动画时间 |
| MCP 无法启动 | command、args、运行环境和包 | 复制整套解释器解决所有问题 |
| 打包找不到文件 | 资源映射、特殊文件名和配套目录 | 只发一个 exe |
| C 盘变满 | 按目录统计磁盘占用 | 直接认定 RAM 泄漏 |
| 测试导入失败 | 当前目录与 PYTHONPATH | 随便下载同名包 |

遇到问题，记录出现时间、角色、模块、操作步骤和第一条错误。不要公开上传含密钥的完整配置。能用一个小文件夹和一个测试角色复现的问题，比“有时不行”更容易修复。

## 24 学习计划与自测

第 1 次练习：安装并使用测试角色，区分听觉和语音，能指出数据在哪里。第 2 次练习：读 main.ts，改一段界面文案并通过构建。第 3 次练习：追踪一次聊天，从前端找到 Agent 的路由和图节点。

第 4 次练习：用空白目录测试文件创建、批准和拒绝，解释访问权限与批准策略。第 5 次练习：读 standby.ts 并通过虚拟时间测试理解待机。第 6 次练习：运行打包自检，检查资源清单，给安装包计算校验值。

完成后应能回答：为什么健康检查不等于声音可用？为什么切换角色要丢弃旧结果？为什么不能把角色设定里的指令当系统授权？为什么删缓存和删记忆不是同一回事？为什么一个安装包不能证明所有电脑都兼容？

不需要一次学会写整个项目。能够解释一条完整数据流、做一个可验证的小修改，并知道哪些数据不能碰，就是可靠的起点。
