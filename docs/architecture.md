# DeskAura 当前架构

更新于 2026 年 11 月 11 日。完整教学见 [零基础教程](learning-guide.md)。

Vue 3 与 TypeScript 负责界面，Three.js 和 three-vrm 负责角色渲染。
Tauri 与 Rust 负责 Windows 窗口、托盘、文件选择器、设备授权和后端进程。

| 服务 | 本机端口 | 职责 |
| --- | --- | --- |
| Agent | 8000 | 配置、人设、对话编排、工具与批准、语音接口 |
| Memory | 8001 | 原始归档、MemU 索引、角色记忆与关系 |
| Motion | 8002 | 动作库、在线生成、结果与播放回执 |

对话基本流程是加载上下文、生成回复、规划动作和保存本轮。流式路径可先输出文字，
再交付动作与最终状态。工具任务根据真实回执继续，受访问权限、批准策略和步骤上限约束。

每个角色有独立配置与凭据作用域、会话命名空间和记忆。项目目录运行使用旁边的
DeskAura-Data；独立安装版使用当前用户 LocalAppData/com.deskaura.app。
WebView IndexedDB 也可能保存模型资料，不能当普通缓存清空。

主页与设置通过角色绑定的增量事件立即同步开关和本地操作，再由后端保存结果更新运行中的同一角色。
界面检测记录与后端短期连接证明分离，只由主动保存配置或检测更新，不随开关操作自动复检。
人设模板默认“无”，不清空已有设定；历史角色保留原配置。

ExpandableContent 统一处理四处内容展开，使用屏幕外副本测量文字，避免改变可见编辑器导致滚动跳顶。
桌宠缩放边界在相机拟合时确定，包围球距离不随视角或动作重新计算；主页预览保持静态。
桌宠窗口不获取键盘焦点，窗口维护不激活；显式前置不关联其他进程的输入线程。

内置 BGE 与 SenseVoice 从 local-models 按需加载。视觉人脸检测在本机执行；
聊天发送屏幕或摄像头图片是另一个需要能力核验和用户确认的流程。

动作有在线、离线、混合模式。腾讯生成返回 FBX，前端解析并重定向；
HY-Motion Worker 返回轴角帧。待机由 standby.ts 调度，随机动作之间插入自然待机。

MCP 默认空配置，通过 stdio、HTTP 或 SSE 对接服务。外部解释器由使用者安装，
不会把开发机 Python/Node 路径作为可移植配置分发。

路径校验和进程树限制不是操作系统沙箱。命令、代码与 MCP 调用需要完全访问，
没有真实隔离执行器时不会宣称已经在系统沙箱中执行。

依赖重建仍需留意三份 requirements 的 Pydantic 约束冲突，详见教程。
安装包未签名，尚需干净机器安装验收。发布边界见 [分发说明](distribution.md)。
